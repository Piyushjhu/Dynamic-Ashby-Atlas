From paper to plot

A map is only as useful
as its trail of evidence.

The website and scientific figures share one literature pipeline. This is how a publication becomes an inspectable region on the map.

01

Discover & register

Start with the paper.

Valency helps find experimental papers and related work. Deduplicate candidates by DOI, then check the primary publication before admitting values. A search result or abstract is a lead, not a measurement.

Register the publication, authors, year, DOI, material classes and a stable link in sources.json. Registered papers awaiting extraction remain visible in the source library; unresolved search leads stay in the review queue.

02

Extract & preserve

Keep the original evidence.

Read the primary publisher or author full text, including the experimental method and table headings, units and footnotes. Preserve the exact material and state, reported values, source-table cells, uncertainty definitions and page locators. Keep a source-file digest so the reviewed version can be identified.

Dynamic evidence enters literature_values.json; reviewed static and ambient properties enter the common property input. Separate the paper’s own experiments from literature comparisons, supplier inputs and numerical simulations. A formula reducing an experimental wave history is not a simulation-only strength result.

03

Audit & admit

Ask what the data actually pair.

A verified pair requires an admitted HEL and spall value tied to the same experimental shot. Independent values, ranges and cross-paper combinations retain their own evidence category.

Reviewed exclusions remain in the ledger. The current compilation contains — verified same-shot pairs.

04

Complete with provenance

Make assumptions visible.

Explicit rules may match a missing coordinate to a reported value for the same material, or to a documented material-state or composition proxy. A conditional yield-strength conversion can estimate HEL when configured.

Every donor and model stays linked. Missing spall is never estimated from yield strength. Unsupported cases remain unresolved.

05

Enclose & classify

Compare named materials.

Pool supported records within each exact named material. A closed ellipse in log space encloses the independent HEL and spall bounds. Class colours connect related materials; fill intensity reflects the count of original extracted records.

Cloud width is a visual convention with a documented minimum. It is not an uncertainty ellipse or a fitted joint distribution.

06

Compare & explore

Keep each property in its context.

The reviewed property input adds static, ambient, thermal and fracture measurements with a paper, table-cell locator, method and material condition. Tensile strength does not become yield strength. K-based toughness, conditional KQ and J-integral results retain their definitions and units; an elastic component of K does not become total fracture toughness.

The static and dynamic maps use independent literature sets. Material clouds enclose supported property extents across recorded conditions; class coverage can combine different alloys. Each support retains its method and source. An optional measured-pair view uses reviewed condition links, while single-property materials remain in the coverage strips. Embeddings use complete-case cohorts and publish features, scaling and available source or stability diagnostics. Missing data do not become class averages or invented pairs.

A separate static reference layer adds 43 material-family ranges from Ashby’s 2021 Tables A3–A4 ↗, with visually checked cells and source locators. Metal yield, polymer nonlinearity and brittle tensile fracture strength retain their own definitions. George, Raabe & Ritchie (2019), Figure 2d ↗ supplies reviewed chart context and source lineage, without turning its outlines into experimental points.

Select Reviewed measurements under Static dataset to see the experimental input alone. Reference bounds do not add measured values or experimental source counts, estimate HEL, or enter rankings and embeddings. Download reference ranges and locators ↓

07

Build & share

Let the repository drive the site.

The website builder reads the canonical literature files, reviewed experimental property input and separate published reference ranges, then runs the audit, completion, cloud and property-analysis functions. It regenerates the interactive data, source library, coverage counts and downloadable CSV together.

A repository update triggers a fresh build in GitHub Actions. The website build reads literature inputs only and never loads private study overrides.
