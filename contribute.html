A living compilation

The next paper
belongs in the same workflow.

Maintainers add reviewed evidence to the research repository. The map, source library and downloads update together on the next build. The public website repository holds the generated site.

View published website files ↗

Three files to know.

sources.json

The publication registry. Add a unique source ID, exact citation, title, year, DOI, link, classes and extraction status.

literature_values.json

The evidence ledger. Add unique record IDs, the source ID, exact material and state, reported properties, units, conditions and extraction locators.

literature_clouds_config.json

Class order, distinct class colours, material colour families and rendering settings. Extend this when adding a new material class.

Optional donor matches and yield-to-HEL inputs belong in exploratory_ashby_config.json. Do not enter inferred coordinates as reported measurements. The generated CSV and website data are outputs.

Before the record becomes a cloud

  1. Open the original paper and verify the values.
  2. Record the exact material and specimen state.
  3. Preserve units, limits and uncertainty definitions.
  4. Confirm whether the properties belong to the same shot.
  5. Attach a stable publication link and an extraction locator.
  6. Leave an unsupported counterpart missing.

Run locally

Build. Preview. Review.

With the project’s Python environment active, run these commands from the repository root.

Refresh scientific figures and the common literature export
python plot_literature_clouds.py
Build the website and serve it locally
python scripts/build_website.py
python -m http.server 8000 --directory _site
Then open http://localhost:8000. Serve the generated folder; opening an HTML file directly will not load its data.

The builder reads the canonical JSON inputs, calls the shared scientific functions, and writes a deployable static website into _site/. No JavaScript package installation or external chart service is needed.

Automatic updates

A commit becomes
a fresh compilation.

GitHub Actions checks the repository, builds the website and saves a downloadable site artifact. With GitHub Pages configured, successful main-branch builds also deploy the website.

New sources, evidence records, classes, clouds and coverage counts are generated from the inputs. Publication-only additions appear in the library immediately; they enter the map after supported numerical evidence is extracted.

The website build always excludes private current-study data and local configuration overrides.
