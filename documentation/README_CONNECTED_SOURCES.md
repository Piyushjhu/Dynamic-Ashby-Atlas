# Evolving experimental data sources

The atlas can refresh an HT-MDEC/Girder folder or collection without copying its
measurements into the literature ledger. Open **Add data → Connect an evolving
dataset** on the website to generate a connection configuration. The public
website never receives an API key or calls HT-MDEC directly.

## What runs where

1. A token-free configuration lives at `data/connected_sources/<id>.json` in the
   research repository. The configuration identifies the root folder, format,
   field mappings, units, authentication reference and publication decision.
2. GitHub Actions runs the Website workflow at minute 17 of each hour, on main
   branch pushes, or through **Actions → Website → Run workflow**. GitHub may
   delay scheduled jobs. This is polling, not an instantaneous webhook.
3. The server-side connector enumerates nested folders, items and files. It
   converts approved experimental rows into an ignored `.connected_sources/`
   snapshot. No raw downloads or credentials are written to that cache.
4. The offline website builder exports `data/connected-experiments.json` and
   rebuilds the explorer. Choose **Connected experiments** or **Both** to view
   the new layer. Clicking a cloud or measurement opens its original item link,
   reported values, units and content hash.

The literature bibliography, counts, static/dynamic rankings and embeddings
remain based on the reviewed literature compilation. Connected measurements
do not silently enter these analyses. Local Cu–Ti study inputs remain excluded;
the connected-feed importer also blocks Cu–Ti material records.

## First example: DiMarco et al. (2023)

The configured example is this [HT-MDEC publication folder](https://data.htmdec.org/#collection/6425a25b451ac6d71ef10cc6/folder/6425a26f451ac6d71ef10cc7).
It is publicly readable and therefore does not require a credential. The
configuration enables public inventory monitoring with `format: discovery`.
This only counts item containers across the folder tree; it does not download measurement
files or publish experimental values. New configurations generated by the
setup form start with `publicApproved: false` until a maintainer approves them.

A read-only schema inspection found `Data_Summary_Final.xlsx`, including
`Spall Strength (est)`, `Peak Shock Stress`, sample/launch identifiers and
processing information. There is **no HEL column**. Sampled nested CSV files
were long-form signal-processing inputs or impact-velocity results, rather
than paired HEL/spall tables. Peak shock stress is not HEL. The workbook's
estimated spall designation must be retained and its reduction/units reviewed
before numerical admission. No experimental values from this example were
copied into the literature dataset or published on the map.

The hourly Website workflow monitors this folder and publishes inventory
counts and refresh status only. File totals are not inventoried in discovery
mode. To import measurements, supply a supported
CSV/JSON export or item metadata with explicit fields below. XLSX and long-form
property tables are not yet adapters; the connector never guesses their layout.

## Secure credential setup

For a restricted source, select `auth.mode: api_key` and a reference such as
`auth.credential: lab-experiments`. In the **research repository**, go to
**Settings → Secrets and variables → Actions → New repository secret**.
Create `ASHBY_DATA_SOURCE_CREDENTIALS` with a JSON object mapping credential
references to their API keys:

```json
{"lab-experiments": "YOUR_API_KEY"}
```

Enter the real value only in GitHub's encrypted secret editor or your local
process environment. Keep it out of chat, configuration JSON, commit messages
and website forms. Several connections can use separate dictionary entries.
Prefer a read-only Girder API key (`core.data.read`) and an account with only
the needed collection access. That API-key scope restricts operations; the
account's ACL controls which data it can read.

For each run, the connector exchanges the API key at `POST /api_key/token`
for a short-lived token and sends it as `Girder-Token`. An existing temporary
token is supported through `auth.mode: token`, but will need replacement when
it expires. Public feeds use `auth.mode: none`. No account password is required.

## Supported measurement schema

Each CSV row, JSON object or item's `meta` object represents one experiment.
CSV mappings use exact column headers; JSON and metadata mappings also support
dotted paths. JSON defaults to an array, or uses the configured `recordsPath`.
Select only intended files using `filePattern`, for example `*-ashby.csv`.

Required mapped fields are `id`, `material`, `class`, and `basis`, plus at least
one of `hel` or `spall`. Optional fields are `state`, `shot`, `method`, and
`temperatureC`. Paired rows require a nonempty mapped `shot` and
`pairing: same_experiment`. IDs must be stable within the whole connection,
including across files; row numbers and filename-dependent IDs are unsuitable.
Duplicate record or experiment IDs reject the source refresh rather than
inflating sample counts. Use the material classes in
`literature_clouds_config.json` exactly.

HEL is the longitudinal elastic precursor stress. Spall is dynamic tensile
failure stress. Set explicit units for each mapped property: `Pa`, `kPa`,
`MPa` or `GPa`. Blank coordinates remain missing; zero cannot appear on a log
axis. Only positive same-experiment pairs enter connected clouds. No analogue,
yield-to-HEL estimate or cross-file pairing supplies a missing coordinate.

The per-row `basis` must be one of `experimental`, `experimental_measurement`,
`direct_measurement`, or `experimental_reduction`. Simulation, model and
unreviewed rows are held out and counted in status diagnostics. An experimental
reduction is not an independent direct stress measurement: its designation is
shown in the evidence details. Declaring a whole mixed file experimental does
not replace per-row identification. Public approval remains the maintainer's
responsibility to check definitions, methods and permission to publish.

Clouds group exact material, state, class, method and temperature **within a
connection**. They enclose observed extents with the same closed log-space
geometry as the atlas. Darker fill indicates more accepted rows. Minimum width
is a drawing convention, not measured uncertainty or a confidence region.

## Refresh behavior and limits

Every run scans the whole selected root with bounded pagination. Source bytes
are re-read and hashed, because item timestamps alone do not reliably identify
file changes. A complete successful scan applies additions, revisions and
deletions together. File errors, invalid values, duplicate IDs, access failures
or interrupted pagination preserve the last good snapshot and mark it stale.
Changing the configuration invalidates older snapshots; disabling a source or
revoking approval immediately removes its records on the next website build.

Only approved normalized snapshots are cached between trusted main-branch
workflow runs. Pull requests neither load that cache nor receive credentials
or contact upstream feeds. The cache can be evicted by GitHub; after eviction,
an unavailable upstream source has no last-good snapshot to retain. A successful
sync rebuilds it. Scheduled GitHub workflows may be disabled after prolonged
repository inactivity. Last-checked/last-success timestamps make missed updates
visible.

Requests use certificate-verified HTTPS pinned to a checked public IP, finite
timeouts and request/file/row limits. Redirected downloads are rejected rather
than forwarding credentials to another host. If a Girder instance uses S3
redirects, export a directly served CSV/JSON or add a separately reviewed
adapter. Raw trace TXT files and XLSX workbooks are not downloaded by discovery.

## Local run

With credentials already set securely in the process environment, run:

```sh
python scripts/sync_data_sources.py
python scripts/build_website.py
python -m http.server 8000 --directory _site
```

`build_website.py` is deliberately offline and works without credentials.
Inspect the source's status in **Add data** and review the connected layer in
**Explore** before enabling publication. Numerical models remain unchanged
until a separate reviewed admission into the scientific compilation.
